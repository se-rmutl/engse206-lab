# ENGSE206 Week05 Rubric and Checklist

> **คะแนนแนะนำ:** 4 คะแนน  
> **Artefact หลัก:** `docs/05-requirement-backlog.md`

## 1. Rubric

| Criteria | 1 คะแนนเต็ม | 0.5 คะแนน | 0 คะแนน |
|---|---|---|---|
| Traceability | ทุก requirement มี Source RC และ Evidence/Need Trace ที่ตรวจได้ | มี trace บางส่วนแต่ยังไม่ครบหรือยังคลุมเครือ | ไม่มี trace หรืออ้างหลักฐานไม่ได้ |
| Classification | แยก Functional/NFR/BR/Constraint/Issue ได้เหมาะสมและมีเหตุผล | มี type แต่บางข้อยังปนกันหรือควร split | จัด type ผิดเป็นส่วนใหญ่ |
| Prioritization | Priority มี rationale จาก value/risk/urgency/dependency | มี priority แต่เหตุผลยังสั้นหรืออิงความรู้สึกบางส่วน | ไม่มีเหตุผล หรือ priority ไม่สัมพันธ์กับหลักฐาน |
| Backlog Quality | มี Req ID, statement, status, open question, Week06 use ครบ | โครงสร้างครบบางส่วนแต่ยังขาด status/open question/Week06 use | backlog อ่านยาก ขาด field สำคัญ หรือไม่พร้อมใช้ต่อ |

## 2. Quick Checklist for Instructor

- [ ] Requirement แต่ละข้ออ้าง Week04 ได้
- [ ] ไม่มี solution ที่ถูกยกระดับเป็น requirement โดยไม่มี need
- [ ] Unknown/policy issue ถูกแยกเป็น `Issue`, `Needs Follow-up`, หรือ `Hold`
- [ ] รายการ `Ready for Week06` มีพอสำหรับทำ model ชุดเล็ก
- [ ] Submission มี commit/link หรือหลักฐานการส่งตามที่กำหนด

## 3. Feedback Stems

ใช้ประโยคสั้น ๆ เพื่อ feedback ในห้อง:

- “ข้อนี้มีหลักฐานจาก E-ID ใด”
- “นี่เป็น requirement หรือเป็น design choice”
- “Priority นี้สูงเพราะ value/risk อะไร”
- “ถ้ายังไม่รู้ policy ให้ mark เป็น Hold ก่อน”
- “ข้อใดพร้อมส่งต่อ Week06 และเพราะอะไร”
